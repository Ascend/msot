# 1. 概述

## 1.1 简介

昇腾芯片本身内部有多个核心，基于昇腾芯片的开发需要小心地处理各个核心负责的内存块，同时，片上内存有对齐的要求，容易产生内存踩踏、内存对齐、内存初始化、流水竞争等问题。本工具提供内存检测、竞争检测等检测功能，帮助用户快速识别并定位此类问题。

本次需新支持的功能如下：

- 支持纯SIMT算子异常检测
- 支持CATLASS DSL算子异常检测
- ops-transformer算子仓检测准确率提升
- 寄存器检测支持展示使用非默认值mask寄存器的vector指令
- 支持DCCI检测

## 1.2 动机

### 1.2.1 支持纯SIMT算子异常检测

AscendC为了支持竞品代码的算子迁移，提供了pure simt算子编写能力，pure simt算子通过特殊runtime接口下发kernel，与既有算子的编程模型差异较大，开发者较难发现越界、踩踏、竞争等异常，需要mssanitizer工具与算子协同实现runtime接口劫持与动态插桩，复用既有检测算法，补齐纯SIMT算子的调试调优能力。

### 1.2.2 支持CATLASS DSL算子异常检测

CATLASS DSL编程语言即将发布，开发者使用该语言编写算子时同样面临越界、竞争、未初始化内存等问题，需mssanitizer工具支持该编程语言的异常检测，提升编程易用性。

### 1.2.3 ops-transformer算子仓检测准确率提升

mssanitizer在部分开源算子仓使用时误报率较高，影响用户对检测结果的信任，需要对ops-transformer算子仓进行全量扫描，识别并修复误报问题，降低误报率。

### 1.2.4 寄存器检测支持展示使用非默认值mask寄存器的vector指令

AscendC API中可能存在隐式的修改特殊寄存器的行为，比如vector mask寄存器，当开发者不知道寄存器被修改，以此为前提进行编程，容易出现精度、功能问题，因此期望mssanitizer工具可以辅助开发者识别寄存器不处于默认值的指令，提高定位效率。

### 1.2.5 支持DCCI检测

kernel函数在多核处理数据时，经常需要核A写入GM后通知核B从GM读出数据，由于每个核具有独立的Data Cache，为使该过程正常运行，需要利用DCCI指令使核A写入后让cache写回GM，核B读出数据前利用DCCI指令刷新cache把最新数据从GM取回，保证两个核的cache一致性，当一致性未被保证时，数据无法在核间被正确读取，此类问题一般隐藏较深、定位麻烦，需mssanitizer支持识别此类场景中DCCI指令漏插的问题。

## 1.3 目标

- 纯SIMT算子异常检测目标：复用既有检测算法，通过runtime接口劫持与动态插桩，支持越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、SIMT内sync_thread同步检测。
- CATLASS DSL算子异常检测目标：支持越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、同步检测。
- ops-transformer算子仓检测准确率提升目标：全量扫描ops-transformer算子仓，最终误报率<5%。
- mask寄存器检测目标：支持展示使用非默认值mask寄存器的vector指令，包括normal/counter模式、vector mask值。
- DCCI检测目标：识别核间一读一写时是否存在DCCI指令漏加的问题。

# 2. 用例分析

## 2.1 支持纯SIMT算子异常检测

参考asc样例算子仓纯SIMT算子样例，使用mssanitizer对pure simt算子进行异常检测，可正常完成检测：

1. 越界、非对齐、线程间踩踏检测。
2. 线程间竞争。
3. 读未初始化内存。
4. SIMT内sync_thread同步检测。

## 2.2 支持CATLASS DSL算子异常检测

修改一个CATLASS DSL算子，构造越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、同步异常，使用mssanitizer拉起算子，可正常完成检测。

## 2.3 ops-transformer算子仓检测准确率提升

覆盖ops-transformer仓所有算子，通过算子仓提供的用例作为单算子用例，完成全量扫描，识别误报问题并修复，最终误报率<5%。

## 2.4 寄存器检测支持展示使用非默认值mask寄存器的vector指令

构造AscendC算子，vector指令调用前配置mask，使用工具可展示vector指令使用的mask寄存器值，包括normal/counter模式及mask值。

## 2.5 支持DCCI检测

构造核间一读一写场景，覆盖以下三类场景，缺失DCCI时，工具可检测到：

1. 核A SetValue + DCCI；核B DCCI + GetValue
2. 核A MTE3；核B DCCI + GetValue
3. 核A SetValue + DCCI；核B MTE2

# 3.方案设计

## 3.1 总体方案

### 3.1.1 支持纯SIMT算子异常检测

pure simt算子通过特殊runtime接口下发kernel，与既有算子的下发方式不同，编译器对SIMT指令的插桩方式与SIMD指令也不同，需mssanitizer工具与算子协同：一方面劫持特殊runtime接口，识别pure simt算子的kernel下发；另一方面通过动态插桩方式记录SIMT线程的内存访问、同步等行为，将各线程的内存访问记录纳入既有检测框架，复用既有检测算法完成越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、sync_thread同步检测。

### 3.1.2 支持CATLASS DSL算子异常检测

CATLASS DSL作为新编程语言，其kernel编译流程与AscendC不同，需工具在CATLASS DSL的编译链路中接入插桩，将指令记录接入既有检测框架，复用既有检测算法完成越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、同步检测。

### 3.1.3 ops-transformer算子仓检测准确率提升

以ops-transformer算子仓RP2 release版本为基线，使用算子仓提供的用例作为单算子用例进行全量扫描，对识别出的误报进行根因分析，区分是检测算法逻辑缺陷、插桩方式导致的误报，还是对合法编程模式覆盖不全，针对性地优化检测算法并回归验证，最终达成误报率<5%的目标。

### 3.1.4 寄存器检测支持展示使用非默认值mask寄存器的vector指令

在指令分析阶段跟踪vector mask寄存器（normal/counter模式）的写入与使用，记录每条vector指令执行时所使用的mask寄存器状态，当mask寄存器不处于默认值时，展示该vector指令及对应mask寄存器的模式与值。

### 3.1.5 支持DCCI检测

DCCI检测采用指令序列模式匹配的方式，按照"SetValue(addr)的下一条指令是否紧跟DCCI(addr)"以及"GetValue(addr)的上一条指令是否紧跟DCCI(addr)"的模式进行检测，识别核间一读一写场景中DCCI指令漏插的问题，针对scalar上的DCCI进行检测，A5场景与A2/A3场景检测模式保持一致。

## 3.2 技术选型（可选）

方案设计简单，不涉及多重选型。

## 3.3 安全隐私与DFX设计

*结合场景用例，对本提案所涉及的安全隐私及DFX（兼容性、可维护性、可测试性、可靠性...）等属性影响进行设计。*

### 3.3.1 支持纯SIMT算子异常检测

兼容性：作为额外选项启用，与原检测能力不冲突。

可靠性：复用既有检测算法，通过runtime接口劫持与动态插桩实现，覆盖pure simt算子编程模型下的越界、竞争、初始化、同步等异常。

### 3.3.2 支持CATLASS DSL算子异常检测

兼容性：作为额外选项启用，与原检测能力不冲突。

可靠性：检测算法复用，仅在CATLASS DSL编译链路接入插桩，功能覆盖与AscendC保持一致。

### 3.3.3 ops-transformer算子仓检测准确率提升

可靠性：以RP2 release版本作为基线，扫描结果可回归对比，保证误报率持续收敛至<5%。

### 3.3.4 寄存器检测支持展示使用非默认值mask寄存器的vector指令

兼容性：通过子命令按需开启，不影响默认检测流程。

可靠性：mask寄存器状态跟踪覆盖normal/counter两种模式。

### 3.3.5 支持DCCI检测

兼容性：作为额外选项启用，与原检测能力不冲突。

可靠性：检测模式固定，仅针对scalar上的DCCI进行检测，A5场景与A2/A3场景检测模式保持一致。

## 3.4 编程与调用设计

### 3.4.1 编程模型基本设计

mssanitizer提供命令行cli，未新增API调用，开发环境直接使用CANN环境。

### 3.4.2 接口定义与设计

#### 3.4.2.1 寄存器检测支持展示使用非默认值mask寄存器的vector指令

- 命令行参数：使用子命令开启mask寄存器检测功能

#### 3.4.2.2 支持DCCI检测

- 命令行参数：`--dcci-check <yes/no>`，默认值：`no`

### 3.4.3 使用说明

以上新增参数均不影响原有参数使用。

# 4.测试设计

*介绍该功能的测试方法以及测试用例设计，包括单元测试（unit test），集成测试（integration test），端到端测试（e2e test）等。*

## 4.1 单元测试

按照原UT测试框架满足覆盖率要求即可。

## 4.2 端到端测试

- 算子类型：mix、cube、vec、simt
- 编程语言：AscendC、Triton、CATLASS、SHMEM
- 调起方式 ：<<<>>>、ACLNN、PTA
- 款型：A2/A3/A5/950

### 4.2.1 支持纯SIMT算子异常检测

参考asc样例算子仓纯SIMT算子样例，构造越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、sync_thread同步异常场景。

### 4.2.2 支持CATLASS DSL算子异常检测

构造使用CATLASS DSL的算子用例，覆盖越界、非对齐、线程间踩踏、线程间竞争、读未初始化内存、同步异常场景。

### 4.2.3 ops-transformer算子仓检测准确率提升

以RP2 release版本为基线，全量扫描ops-transformer算子仓，统计误报率并回归验证，验收平台为Ascend950。

### 4.2.4 寄存器检测支持展示使用非默认值mask寄存器的vector指令

构造AscendC算子，vector指令调用前配置mask，覆盖normal/counter模式，验收平台为A2/A3。

### 4.2.5 支持DCCI检测

构造"核A SetValue + DCCI；核B DCCI + GetValue"、"核A MTE3；核B DCCI + GetValue"、"核A SetValue + DCCI；核B MTE2"三类场景，构造DCCI缺失，验证可检出，验收平台为A2/A3/A5。
